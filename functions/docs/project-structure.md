# Project Structure — bake-ry / functions

Firebase Functions + Express.js API. Multi-tenant (bakery-scoped), factory-pattern architecture.

## Root

```
functions/
├── src/                     # all application code
├── scripts/                 # dev tooling (filename-case check, schema snapshot)
├── docs/                    # documentation
├── coverage/                # jest output (gitignored)
├── package.json
├── jest.config.js
├── eslint.config.js / .eslintrc.js
├── firestore.rules          # (at repo root, one level up)
└── CLAUDE.md                # AI/dev guidance
```

## src/ — layered by responsibility

```
src/
├── index.js                 # Express app entry, mounts all routes, exports the Function
│
├── config/
│   ├── firebase.js          # firebase-admin init (db, auth)
│   └── createCustomToken.js
│
├── routes/                  # one file per resource — URL wiring + middleware only
│   ├── <resource>Routes.js  # e.g. orderRoutes, productRoutes, recipeRoutes
│   └── ...                  # ~17 route files
│
├── controllers/             # HTTP layer — parse req, call service, shape response
│   ├── base/
│   │   └── controllerFactory.js   # generates standard CRUD controllers
│   └── <resource>Controller.js
│
├── services/                # business logic + Firestore access
│   ├── base/
│   │   ├── serviceFactory.js      # generates standard CRUD services
│   │   └── recordHistory.js       # writes updateHistory subcollection (in txn)
│   ├── versioning/
│   │   └── recipeVersioning.js
│   ├── recipeGraph.js             # domain-specific helpers live alongside services
│   └── <resource>Service.js
│
├── models/                  # data shapes + Firestore (de)serialization
│   ├── base/
│   │   └── BaseModel.js           # id/createdAt/updatedAt, date handling, to/from Firestore
│   └── <Entity>.js               # extend BaseModel — Bakery, Order, Product, Recipe, User…
│
├── middleware/
│   ├── userAccess.js              # authenticateUser + role checks
│   ├── bakeryAccess.js            # hasBakeryAccess (tenant scoping)
│   ├── subscriptionAccess.js
│   ├── errorHandler.js            # maps custom errors → HTTP responses
│   ├── requestLogger.js
│   └── request_logs/
│
├── utils/
│   ├── queryParser.js             # pagination / sort / date-range / filters
│   ├── errors.js                  # BadRequestError, NotFoundError, ForbiddenError, AuthenticationError
│   ├── dateUtils.js  periods.js  helpers.js  validators.js
│
├── functions/                # standalone Cloud Functions (non-Express triggers)
│
├── seeds/                    # data seeding + backups (dev/ops only)
│   ├── seedConfig*.js             # per-bakery config (pastellus, diana_lee)
│   ├── saveBackup.js
│   ├── data/                      # raw seed data
│   ├── firestore/
│   └── runners/                   # executable seed scripts (npm run seed:*)
│       └── cleanup/               # one-off migration shell scripts
│
└── __tests__/                # mirrors src/ layout
    ├── setup/                     # jest setup, emulator config
    ├── test_data/
    ├── controllers/  services/  models/  routes/  utils/  middleware/
```

## Request flow

```
route → middleware (auth → bakery access → role) → controller → service → model → Firestore
                                                        ↓
                                              errorHandler (on throw)
```

## Conventions

- One file per resource across routes/controllers/services/models, named consistently
  (`orderRoutes.js` → `orderController.js` → `orderService.js` → `Order.js`).
- CRUD is generated by the three factories; only non-standard logic is hand-written.
- Multi-tenant: every resource path is `bakeries/{bakeryId}/<resource>`.
- All models extend `BaseModel`; all updates auto-record history via `recordHistory`.
